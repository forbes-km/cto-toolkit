# Enterprise Architecture and Operating Model

- **EA Definition** - a working definition of what enterprise architecture is and is not, used to frame scope and expectations before the other methods in this section are applied.
- **Business Capability Model** - a reference method for building a capability-led view of the organization, used as the anchor artifact that roadmaps, investment cases, and operating model work all reference back to.
- **Operating Model Canvas** - a one-page diagnostic covering accountability, workflow, decision rights, information, technology, and locations, used to make an operating model explicit before or during change.
- **EA Operating Model** - defines how an enterprise architecture function itself should be structured, staffed, and operated: roles, demand management, and the behaviors that separate respected EA functions from resented ones.
- **Architecture Review Operating Model** - a governance model that engages delivery teams early instead of approving late, built for organizations where traditional review boards have become a drag on delivery rather than a help.
- **Architecture Principles Library** - fourteen strategic, technical, data, and people/process principles, each with the reasoning behind it, meant to guide decisions rather than sit unused in a wiki.
- **EA Maturity Assessment** (workbook + facilitator guide) - a six-dimension scoring instrument for baselining enterprise architecture maturity, with a structured method for running the assessment honestly and turning results into a real improvement plan rather than a grade.
- **Security & Zero-Trust Maturity Model** - a parallel six-dimension scoring framework (identity and access, segmentation and blast radius, detection and response, vulnerability management, third-party risk, governance and culture) for assessing enterprise security posture against a zero-trust target architecture, scored against evidence rather than intent.
